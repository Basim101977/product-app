# تشغيل حاضر واختباره على الجهاز الجديد

هذه أدوات تسليم جديدة، وليست تعديلًا للنسخة الأصلية المحفوظة على الجهاز السابق. مجلد `source` يحتفظ بمسارات المشروع والاختبارات المطلوبة. أُجيز تنقيح نسختَي `index.html` الحالية والتاريخية داخل التسليم فقط لإزالة بيانات البذور الافتراضية الحساسة؛ الأصول تبقى دون تغيير، وتُوثّق الفروق في سجل الحزمة. لذلك لا تفترض أن ملفات التسليم مطابقة بايتًا للأصول أو تصلح نسخة استرجاع للإنتاج. الاختبارات المحلية تستعمل حسابات وطلبة اصطناعيين؛ لا تحتاج تسجيل دخول Firebase ولا مفاتيح خدمة.

> **تنبيه مهم:** الملف الأصلي `netlify_site/runtime-config.js` يشير إلى مشروع الإنتاج الحقيقي. فتح الموقع الخام عبر خادم محلي لا يجعله بيئة تجريبية؛ تسجيل الدخول وتشغيل الأزرار قد يصلان إلى الإنتاج. استخدم الاختبارات أو المعاينة الآمنة أدناه، ولا تشغّل `firebase deploy` أثناء الإعداد.

## 1. بنية الحزمة

```text
مجلد-التسليم/
  docs/SETUP-AND-TESTS.md             ← هذا الدليل
  support/                           ← أدوات التشغيل الجديدة
  source/work/
    hathir-production-upgrade-20260922/app/
    hathir-mobile-actions-20260919/candidate/netlify_site/
```

لا تغيّر اسم المجلدين أو المسافة النسبية بينهما. الثاني يحتوي ملفات مرجعية مشتقة من الإصدار القديم لاختبار الترقية؛ ليس نسخة بيانات ولا مشروعًا مطلوب نشره. عينة `index.html` التاريخية المخصصة للتسليم تستبعد كلمات المرور التجريبية وقائمة الأسماء الافتراضية غير اللازمة؛ لذلك ليست مطابقة بايتًا لملف الإنتاج القديم ولا تصلح نسخة استرجاع له. اختبارات الترقية تتحقق من سلوك العينة المنقحة المعتمدة، وليست مقارنةً إثباتيةً مع جميع بايتات الإصدار القديم المنشور. لا تنقل ملف التاريخ الخام بدلها، ولا يلزم نقل مجلد العمل القديم كاملًا.

## 2. الإصدارات المثبتة التي جرى التحقق منها على الجهاز الأصلي

| المكوّن | الإصدار | استخدامه |
|---|---|---|
| Node.js | 22.20.0 | تشغيل الاختبارات؛ المشروع يستهدف Node 22 |
| npm | 10.9.3 | تثبيت الحزم من ملفات القفل |
| Firebase CLI | 15.30.0 | أداة إدارة منفصلة؛ لا تحتاجها الاختبارات لتسجيل الدخول |
| Playwright | 1.62.1 | تشغيل اختبارات المتصفح |
| Google Chrome | 153.0.8010.53 | المتصفح المستخدم في التحقق الأصلي؛ يمكن توفير Chromium الخاص بـ Playwright |

| Firestore emulator | 1.22.0 | التحقق الحقيقي من القواعد محليًا |
| firebase-admin | 14.4.0 | مثبت بواسطة ملف قفل `functions` |

`support/package.json` يثبت إصدارات الأدوات دون `^` أو `~`. أما حزم الوظائف فيجب تثبيتها بواسطة `functions/package-lock.json` الأصلي، لا تحديثها عشوائيًا. الإصدارات أعلاه نتائج جرد الجهاز الأصلي، وليست ادعاءً بأن أي إصدار أحدث مجرّب.

## 3. تجهيز Windows

ثبّت [Node.js](https://nodejs.org/en/download) من سلسلة 22، و[Java Temurin 21](https://adoptium.net/installation). يوصى بإغلاق PowerShell وإعادة فتحه بعد التثبيت. مثال تثبيت Java عبر Windows Package Manager، إذا كان متاحًا:

```powershell
winget install --exact --id EclipseAdoptium.Temurin.21.JDK
node --version
npm.cmd --version
java -version
```

افتح PowerShell داخل مجلد التسليم ثم نفّذ:

```powershell
Set-Location .\support
npm.cmd ci --ignore-scripts --no-audit --no-fund
npx.cmd --no-install playwright install chromium
npm.cmd run install:emulator

Push-Location ..\source\work\hathir-production-upgrade-20260922\app\functions
npm.cmd ci --ignore-scripts --no-audit --no-fund
Pop-Location

$env:PERSONAL_TEST_JAVA = (Get-Command java.exe -ErrorAction Stop).Source
npm.cmd run check
npm.cmd test
```

تنزيل Chromium يتم بالأداة الرسمية كما توضح [وثائق Playwright](https://playwright.dev/docs/browsers). محاكي القواعد يحتاج Java؛ التفاصيل العامة في [وثائق Firebase للمحاكيات](https://firebase.google.com/docs/emulator-suite/install_and_configure). اختبارات هذه الحزمة تشغّل JAR مباشرةً، لا أوامر CLI متصلة بالحساب.

أوامر التثبيت تحتاج إنترنت لتنزيل حزم عامة. بعد اكتمالها تعمل حزمة الاختبارات دون الوصول إلى Firebase الحقيقي. لا توجد كلمات مرور أو مفاتيح خاصة ضمن أوامر التثبيت. لا تنقل ملفات `.config/configstore/firebase-tools.json` أو ملفات Service Account أو جلسات المتصفح إلى الحزمة.

### استخدام Java أو Chrome أو المحاكي الموجود مسبقًا

يمكن تحديد مسارات ملفات تنفيذية موجودة بدل تنزيل متصفح إضافي أو المحاكي. المسارات التالية أمثلة؛ استبدلها بمسارات الجهاز الجديد:

```powershell
$env:PERSONAL_TEST_JAVA = 'D:\Tools\Java21\bin\java.exe'
$env:CHROME_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
$env:PERSONAL_TEST_FIRESTORE_JAR = 'D:\Tools\firestore-emulator-v1.22.0.jar'
npm.cmd run check
npm.cmd test
```

بديل Java هو ضبط `JAVA_HOME` إلى مجلد Java 21. إذا لم تحدد `CHROME_PATH` يستخدم المشغّل Chromium الخاص بحزمة Playwright المثبتة. لا يعتمد على مجلدات Codex أو اسم مستخدم الجهاز السابق.

## 4. ما الذي يفعله المشغّل المحمول؟

`run-tests.cjs` يتحقق من Node 22، المتصفح، Java 21، حزم الوظائف، الملفات المرجعية وSHA256 للمحاكي، ثم يشغّل **ملف الاختبارات الأصلي دون تعديله**: `tests/run-local.cjs` داخل النسخة المنقولة.

يمرّر متغيرات البيئة التي تدعمها الاختبارات أصلًا: `PLAYWRIGHT_MODULE` و`CHROME_PATH` و`NAME_QR_GENERATOR_JS` و`NAME_QR_DECODER_JS` و`PERSONAL_TEST_JAVA` و`PERSONAL_TEST_FIRESTORE_JAR`. لا يوجد ترقيع للكود أو تغيير مساراته الداخلية. كما يزيل إعدادات اعتماد/نشر السحابة المعروفة من بيئة عملية الاختبار؛ هذا إجراء احتياطي، وليس بديلًا عن عدم وضع مفاتيح داخل الحزمة.

تغطي الحزمة الاختبارات الاصطناعية، المتصفح، QR، طابور الحضور المعلّق، الترقية الفعلية لـ Service Worker، وFirestore Rules على عنوان loopback ومشروع `demo-` فقط. تقارير النتيجة والصور الجديدة تُكتب في:

```text
source/work/hathir-production-upgrade-20260922/app/reports/
```

الملف الجامع هو `local-regression-summary.json`. يجب أن يكون `passed: true` وأن تمر جميع الأجنحة؛ لا تعتمد على عدد الاختبارات وحده أو على تقرير قديم داخل الحزمة. سيستبدل التشغيل تقارير **النسخة المنقولة** فقط؛ احفظ تقارير التسليم المرجعية منفصلة إذا أردت مقارنتها.

## 5. معاينة آمنة بلا اتصال بالإنتاج

من مجلد `support`:

```powershell

```

ينشئ هذا صورة لواجهة دخول اصطناعية بعرض 390 بكسل في `support/previews/synthetic-login-390.png` باستخدام حاجز الشبكة والـ Firebase mock الأصليين. ليست معاينةً تفاعليةً للإنتاج، ولا تحتاج Java. لا يفتح رابط خادم خام للمستخدم ولا يسمح بتسجيل دخول حقيقي.

## 7. حدود التسليم والنشر

الملفات `tools/deploy-check.cjs` و`tools/freeze-release.cjs` أصلية وتبقى بلا تعديل. بوابة النشر تشير عمدًا إلى نسخة الأساس الخاصة في `../.private/baseline/manifest.json` وتتحقق من تقرير QA وبصمات الإصدار. ملفات الاعتماد والنسخ الخاصة ليست اعتمادًا مطلوبًا للاختبارات ولا ينبغي وضعها ضمن حزمة عامة.

نجاح الاختبارات لا يمنح إذن نشر ولا يثبت إرسال البريد أو عمل الكاميرا/NFC على جهاز فعلي. لا تتجاوز بوابة النشر أو تصطنع baseline مفقودًا. يلزم قبل أي نشر جديد تسجيل دخول المالك على الجهاز الجديد، التأكد من المشروع/الموقع، نسخة احتياطية حديثة وخطة مراجعة وموافقة منفصلة. `live-public-smoke.cjs` اختبار شبكة منفصل لملفات عامة، وليس ضمن أمر الاختبارات المحلي، ولا يلزم لتجهيز الجهاز.

## 8. تشخيص سريع

- `Packaged original application missing`: شغّلت `support` خارج بنية المجلدات الواردة في القسم الأول.
- `Original release test fixture missing`: بعض ملفات الإصدار القديم المرجعية غير منقولة؛ لا تنسخ بيانات أو backend قديمًا لحلها.
- `Functions dependency ... missing`: نفّذ `npm ci` داخل `app/functions` المنقول، ثم عد إلى `support`.
- `Cannot find module` داخل أدوات الدعم: نفّذ `npm ci` داخل `support`؛ لا تستخدم مسارات الجهاز القديم.
- `Chromium missing`: نفّذ أمر تثبيت Playwright أو حدد `CHROME_PATH` الموجود.
- `Java 21 is required`: حدد `PERSONAL_TEST_JAVA` لملف Java 21 الصحيح؛ وجود Java آخر على PATH لا يكفي.
- `Emulator SHA256 mismatch`: توقف، لا تشغّل الملف المختلف ولا تغيّر قيمة البصمة في الاختبار.
- فشل صلاحيات loopback/المتصفح أو تشغيل Java: راجع الحماية المحلية ورسالة الخطأ، ولا تعالجها بربط الاختبارات بمشروع الإنتاج.
