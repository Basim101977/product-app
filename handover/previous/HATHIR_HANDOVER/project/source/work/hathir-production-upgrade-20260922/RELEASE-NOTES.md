## النطاق والقرار

ترقية المشروع الأصلي `alqar-student-attendance-2026` والموقع `https://hathir.web.app/` بميزات النسخة الشخصية. لا تحويل للموقع إلى مشروع الاختبار، ولا نقل حسابات بين مشروعي Firebase. النسخة الشخصية التجريبية ومشروع حلول القياسات خارج نطاق التغيير.

قرار المستخدم: الحسابات القديمة المعتمدة تدخل دون فرض تأكيد البريد مجددًا؛ الحسابات الجديدة يجب أن تؤكد البريد وتنتظر موافقة المالك. الاستثناء مثبت لـ٢٨ هوية أصلية عند وقت القطع: ٢٧ حسابًا معتمدًا والمالك الحالي. لا تغيير لحقل تأكيد البريد ولا كلمات المرور، ولا فرض تحديث كلمات المرور القديمة عند الدخول.

## حماية التوافق

- إبقاء معرّفات الحسابات ومساحات العمل والطلبة والمحاضرات الأصلية.
- إبقاء قاعدة المتصفح `hathir-offline-v1` وطابور التسجيلات وهوية التطبيق المثبت `/`؛ لا مسح للتخزين المحلي أو ذاكرة التخزين القديمة.
- إبقاء مزامنة الدفعات في `asia-south1` وبقية الوظائف في `us-central1`، وبحساب التشغيل الأصلي.
- قبول بطاقات الرقم القديمة عند تطابق واحد داخل القائمة الحالية، إضافة إلى بطاقات الاسم القديمة والرمز المختصر الجديد. لا قبول لأسماء أو رموز ملتبسة.
- تحميل مصادر الطلبة القديمة دون دمج تلقائي، واحترام القوائم الفارغة أو الممسوحة حتى لا تعود بيانات محذوفة.
- المواد القديمة ذات السنة الدراسية غير المسجلة تتطلب اختيار السنة والمرحلة صراحةً قبل استيراد أسماء جديدة؛ لا تخمين للسنة. حضور الطلبة الحاليين لا يتطلب إعادة رفعهم.
- حماية عدادات الترميز من إعادة استخدام رقم نشط أو مؤرشف. عند تعارض عداد قديم، تتوقف الإضافة دون تغيير البيانات، بدل إعادة ترقيم طلبة موجودين.
- عدم حذف الوظائف الأصلية: ٣٣ اسمًا محفوظًا، مع إضافة ٨ وظائف. أربع وظائف قديمة لإدارة الصلاحيات/تغيير الرموز تتحقق من المستخدم ثم تطلب تحديث التطبيق دون كتابة بيانات.

## النسخة الاحتياطية

المجلد الخاص: `.private/baseline` داخل هذا المجلد. يحتوي ٣٨ مخرجًا مشفرًا، بينها ٤٠٥٨ مستند Firestore بصيغة REST ذات أنواع ثابتة، إعدادات المشروع والقواعد، نسخة الكود المحلية الأصلية، وملف مصدر كل وظيفة أصلية منشورة وعددها ٣٣. وقت اللقطة `2026-09-22T19:14:00.000Z`.

جرى فك التشفير محليًا للتحقق من تجزئة كل ملف. المفتاح محمي بحساب Windows الحالي عبر DPAPI؛ هذه **ليست نسخة قابلة للنقل لجهاز آخر دون إعداد نقل آمن للمفتاح**. لا تتضمن هاشات كلمات مرور Auth أو طوابير الأجهزة الأخرى. لا تدّعي هذه المهمة إجراء استعادة شاملة فعلية. تبقى الحسابات في خدمة Auth الأصلية، والاستعادة الزمنية لقاعدة الإنتاج كانت مفعّلة وقت الفحص.

## أدلة الفحص والنشر

- `app/reports/local-regression-summary.json`: نتائج آخر تشغيل كامل للاختبارات المحلية الاصطناعية.
- `app/reports/promotion-regression.json`: توافق البيانات المحلية والقوائم القديمة والبطاقات وسياسة الدخول.
- `app/reports/personal-rules-emulator.json`: فحص قواعد الأمن في محاكي محلي فعلي.
- `app/reports/release-source-manifest.json`: تجزئات ملفات الإصدار المجمدة؛ يمنع فحص النشر إرسال ملفات تغيرت بعدها.
- `reports/dry-run.json`: تحقق الحسابات والنسخ دون كتابة سحابية.
- `reports/apply-legacy-access.json` و`reports/apply-password-policy.json`: لا يوجدان إلا بعد تنفيذ الخطوتين المحددتين.
- `reports/deployed-all.json` و`app/reports/live-public-smoke.json`: لا يعني وجود المصادر محليًا نجاح النشر؛ يُعتمد الفحص اللاحق والتجزئات.
